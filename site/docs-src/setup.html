Setup

Orbit is a pnpm monorepo: a Node server, a React web client, an Electron desktop shell and an Expo mobile app. Pick the path that fits: run the Docker stack, install the desktop app, or build from source.

Platform notes

# Docker Desktop (or another Docker engine) must be running
git clone https://github.com/raybello/orbit.git && cd orbit
pnpm install && cp .env.example .env

The desktop app ships as a .dmg and .zip for both Apple Silicon (arm64) and Intel (x64). On Apple Silicon a release can also include a native server bundle, so the app runs the stack without Docker Compose for the API (bots still use Docker desktops by default).

# Node 22 via your package manager or nvm, then:
corepack enable && corepack prepare pnpm@12 --activate
# Docker Engine with your user in the docker group
git clone https://github.com/raybello/orbit.git && cd orbit
pnpm install && cp .env.example .env

The desktop app ships as an x64 AppImage. Linux is also the target for servers: the compose stacks and the published images (ghcr.io/raybello/orbit/app) are built for amd64 and arm64.

The desktop app ships as an x64 NSIS installer and uses Docker Desktop to run the local stack. To build from source, use Docker Desktop plus Node 22 and pnpm 12; running the server under WSL2 keeps paths and the Docker socket closest to Linux.

winget install OpenJS.NodeJS.LTS Docker.DockerDesktop
corepack enable
git clone https://github.com/raybello/orbit.git
cd orbit
pnpm install
copy .env.example .env

Run the Docker stack

infra/compose has two stacks. Both run api (port 8787: the API and the built web client) and sandbox-supervisor (no port; it suspends idle bot containers so they do not hold RAM after the API stops). State lives on the orbit-data volume.

From this checkout

cp .env.example .env       # SESSION_SECRET is required
docker compose -f infra/compose/docker-compose.yml up --build
open http://127.0.0.1:8787

From published images

cd infra/compose
cp .env.images.example .env    # SESSION_SECRET: openssl rand -hex 32
docker compose -f docker-compose.images.yml --env-file .env up -d

ghcr.io/raybello/orbit/app:edge tracks main; tagged releases publish versioned tags. The server image's build context is the repository root, because it installs the whole pnpm workspace:

docker build -f apps/server/Dockerfile -t ghcr.io/raybello/orbit/app:edge .

Per-bot Docker computers bind-mount each bot's home from the host, so the folder in COMPUTER_HOME_DIR must exist at the same absolute path inside the api container. Set ORBIT_HOST_DATA and mount it at the same path, or use COMPUTER_KIND=orgo.

Build from source

pnpm install
cp .env.example .env
pnpm build        # packages, web, server, desktop shell
pnpm test         # server, web and desktop suites
pnpm typecheck    # all seven packages

For day-to-day work, run only the pieces you need:

pnpm --filter @orbit/server dev     # API on :8787, tsx watch
pnpm --filter @orbit/web dev        # Vite on :5173, proxies /api to GROKBOT_API or :8787
pnpm --filter @orbit/desktop dev    # build the Electron shell and launch it
pnpm --filter @orbit/mobile start   # Metro for the Expo client

The server serves apps/web/dist when it exists, so pnpm --filter @orbit/web build plus a server start gives you the production UI on the API port.

Desktop app

The desktop app is an Electron shell around the server's own web build. On first launch a setup window asks where Orbit runs: This computer (it starts or attaches to a local Docker Compose stack, or the native server bundle on Apple Silicon), or a server URL. It also helps wire up Hermes. The choice is saved in the app's user data and can be overridden for one launch:

ORBIT_WEB_URL=http://localhost:5173 pnpm --filter @orbit/desktop run dev
# or: electron . --server=https://orbit.example.com

On first run the app checks for, and offers to install, what the local stack needs: Hermes Agent when it is missing; Docker Desktop on macOS and Windows when Docker is missing (on a Mac it downloads the build for your chip, checks Docker Inc's signature, copies it to Applications and starts it); and on the native Mac stack, Apple's container runtime (its signed .pkg, checked against a pinned SHA-256 and Apple's Developer ID signature before macOS asks for your password). The builds are not code-signed yet; the install guide shows the one-time steps to open them.

For testing, ORBIT_USER_DATA_DIR runs the app with a separate profile, and ORBIT_IMAGE_TAG picks the server image tag (for example edge before a release has published its own).

Installers are published to GitHub Releases by desktop-release.yml on v* tags, and the app updates itself with electron-updater. Two scripts speed up local work: scripts/dev-rebuild-loop.sh rebuilds the app image, recreates the stack and relaunches Electron; scripts/dev-vite.sh runs Vite against the running stack when only the UI changed.

Mobile app (iOS and Android)

pnpm --filter @orbit/mobile start          # Metro; open in a dev build
cd apps/mobile && npx expo run:ios         # or: npx expo run:android
eas build --profile production --platform all

The API base comes from EXPO_PUBLIC_API_URL (baked into extra.apiUrl at build time) and can be changed at runtime on the server screen. The sign-in token is kept in expo-secure-store. A release build must use https: the config throws rather than ship a cleartext public URL. A simulator reaches a server on the same Mac at localhost.

Install on a remote computer (Orgo)

  1. On your machine, build and package the server bundle (or use a release bundle), then copy it and scripts/install-on-computer.sh to the computer.
  2. In Orgo, create a public URL for port 8787 on that computer.
  3. On the computer, as root: 
    PUBLIC_URL=https://<name>.orgo.dev ORGO_COMPUTER_ID=<uuid> ALLOWED_EMAILS=you@example.com \
KEYS_FILE=/root/keys.txt PRIMARY_CDP_URL=http://127.0.0.1:9333 \
  bash install-on-computer.sh hq-app.tgz
    The script installs to /opt/hq, adds one supervisor program, and leaves Hermes alone. Running it again with a newer archive upgrades in place.
  4. Give the main agent the app's tools: python3 /opt/hq/app/scripts/add-hq-to-hermes.py adds an mcp_servers.hq entry to Hermes' config.yaml (--remove takes it out).
  5. Open the public URL and sign in.

Wiring up Hermes

  • The first bot is the Hermes agent already running on the machine. Point HERMES_URL at its API server and HERMES_HOME_PRIMARY at its home (default ~/.hermes); the API key is read from <home>/.env or HERMES_KEY.
  • Every other bot gets a managed home under ENGINES_DIR/<botId> (keep it outside ~/.hermes) and a gateway on a port from ENGINE_PORT_BASE (8650) upward.
  • Engines reach the app's tools at MCP_BASE_URL/mcp/<botId>; the host-run primary uses PRIMARY_MCP_BASE_URL when the server runs in a container. On startup the server makes sure the primary's config has its hq MCP entry.

Troubleshooting

  • The server exits at start: SESSION_SECRET is missing.
  • Apps or voice say "not configured": set COMPOSIO_API_KEY or XAI_API_KEY, or install the local voice models.
  • A bot has no screen: check Docker is running and that COMPUTER_HOME_DIR exists at the same path inside the API container.
  • The primary bot cannot use the app's tools: confirm its config.yaml has the hq MCP entry pointing at a URL it can reach.
  • Health check: curl http://127.0.0.1:8787/api/health returns the version, engine and uptime.
