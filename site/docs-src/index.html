Orbit documentation

Orbit is a self-hosted team of AI agents you chat with, each with its own screen on its own computer. These pages cover how to use it, how to set it up on each platform, the HTTP and MCP API, and how the source code is organised.

Key concepts

A few words carry specific meanings across the app, the API and the code.

TermWhat it is
BotAn agent you chat with. It has a name, an avatar shape and colour, instructions, its own memory, a Hermes engine and a computer. Stored as a row in the bots table with kind='agent'.
Primary botA bot flagged as a team coordinator. A primary can talk to and change every other bot and carries a star in the UI. At least one bot is always primary, at most three.
EngineThe Hermes agent that runs a bot. Every bot gets its own Hermes home under ENGINES_DIR and its own hermes gateway run, started by the server. The primary engine (ENGINES_DIR/primary) holds the credentials; each other bot's managed engine (ENGINES_DIR/<botId>) inherits them.
Computer / screenThe Linux desktop a bot works on: a container of its own, running Xvfb, a window manager, Chrome and a VNC server.
Group (room)A bot row with kind='room' and a member list. A room never runs an agent itself: the server dispatches each message to the members who should answer.
RowOne entry in a bot's transcript: a message, a tool call, a card, an event or a notice. Rows are ordered by seq and revised in place while streaming (updatedSeq).
CardA row where a bot stops and asks you something: an approval for a write action, a question with options, a connect request for an app, or a draft to send.
Routine / calendar eventA prompt a bot runs on a schedule. Recurring events use a cron expression; one-time events use a date and time; event routines fire on a Composio trigger.
Task, memory, LibraryA bot's task list, the facts it remembers, and the folder where it saves files it makes.
SkillA SKILL.md in the shared library (written in the app, installed from GitHub, or added by a bot). Every bot has it unless it is turned off for that bot; /name in a message uses it. The Skills section also lists the MCP servers each bot can use.
Connected appA third-party account (Gmail, Slack, GitHub…) connected through Composio. Write actions wait for your approval unless you chose "always allow".

The system at a glance

Desktop app / browser ─┐  HTTP + SSE, WebSocket (VNC, voice)
Mobile app (Expo) ─────┤
                       ▼
             Orbit server  (Node · Hono · SQLite)
               │  POST /v1/responses        ▲  MCP  /mcp/<bot>
               ▼                            │
             Hermes gateway (one per bot) ──┘
               │
             Docker API ──► bot desktop (Xvfb · Chrome · VNC)
             Composio   ──► connected apps
             sherpa-onnx / xAI ──► voice

The server owns the transcript: chat rows, cards, routines and screens live in SQLite, and every change fans out to connected clients over Server-Sent Events. Hermes owns the agent loop, model calls and history; it reaches the app's own tools (tasks, routines, files, the computer, other bots) over MCP. The server supervises each request a bot works on: it retries provider outages for up to 20 minutes, repairs a refused sign-in or a stopped agent, sends a bot that is stuck in a loop back to reassess, and picks up unfinished work after a restart.

Experimental. Orbit has had no security audit. Bots share a Docker host, and only Composio write actions are gated by approval cards; what a bot does in its own browser or shell is not.
